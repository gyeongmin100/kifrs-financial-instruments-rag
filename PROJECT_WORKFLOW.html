공식 문단을 중심으로 구조 관계와 의미 관계를 함께 저장합니다. 모든 문장을 노드로 만들어 그래프를 과도하게 키우지는 않습니다.

LLM에게 전부 맡기지 않습니다. 명시적 근거부터 자동 연결하고, 의미 관계는 후보 생성과 검증을 거칩니다.

1. 구조 연결
   HWPX 계층·문단 순서로 CONTAINS / NEXT / HAS_TABLE / HAS_FOOTNOTE 생성
                      |
2. 명시적 참조
   “제1032호 문단 11”, “문단 5.5.17 참조”를 규칙으로 추출하여 REFERS_TO 생성
                      |
3. 공식 개념
   기준서의 용어 정의표에서 canonical name과 원문에 명시된 alias만 추출
                      |
4. 개념 연결
   본문·표·적용사례에 그 명칭이 정확히 등장할 때만 MENTIONS 생성
                      |
5. 검증
   개수·정의 출처·승인 상태·실제 정의 경로를 Cypher로 재현하여 확인

LLM 추론으로 만든 의미 관계는 사용하지 않습니다. 규칙·조건·예외·사례를 LLM으로 추출하는 방식을 검토·구현했으나, 사람 승인 절차를 운영할 계획이 없어 최종적으로 제거했습니다. 현재 의미 계층은 문자열 일치로 결정되는 Concept·MENTIONS뿐입니다.

현재 진행 상태

파싱·페이지 매핑·구조/참조 그래프·공식 Concept KG·임베딩·Hybrid 검색·단일 답변·FastAPI·제품 UI가 완료되었고, 무료 클라우드 배포(Aura Free + Render + Cloudflare Pages)까지 마쳤습니다. 이후 비동기 작업 API와 이미지 첨부를 추가하고, 사용하지 않는 의미 규칙 KG를 제거했습니다. 2026-07-29에는 기각률 60%와 실행별 결과 변동을 해결하기 위해 질문 분석·그래프 확장·재정렬·충분성 검사·별도 인용 검증(약 1,400줄)을 제거하고 파이프라인을 3단계로 줄였습니다. 남은 한계는 (1) 인용 검증이 형식만 보고 내용 일치는 확인하지 않는 점, (2) 답변이 근거 범위를 넘는지 감지할 장치가 없는 점, (3) 정의를 직접 묻는 질문에서 부록 정의표가 본문 문단에 밀리는 검색 편향, (4) 답변 생성 LLM에 temperature를 설정하지 않아 남아 있는 변동성입니다.

이 문서는 현재 확인된 사실만 완료로 표시합니다. 이후 구현이 끝날 때마다 해당 작업의 상태와 완료 기준을 함께 갱신합니다.
